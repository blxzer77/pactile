# Product and maintainer-local surfaces

A default `pactile init --codex` creates canonical files under `.pactile/` and projects managed instructions and Skills into `AGENTS.md` and `.agents/skills/`. Native Codex bindings depend on host readiness. `pactile update` refreshes framework-owned files after conflict review; `.pactile/spec/` remains user-owned.

The maintainer's local harness can contain private tasks, research, indexes, worktrees, and host configuration. Those files are not product templates and are not copied into a consumer project.

If a capability seems absent, inspect the package's generated files and the output of `pactile capability-smoke --json`. Do not copy files from a maintainer workspace into a consumer project.
