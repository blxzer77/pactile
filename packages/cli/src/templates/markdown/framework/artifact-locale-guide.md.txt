# Artifact language and audience

Human-authored PRD, design, implementation, verification and handoff prose follows the user's/project's review language. Machine identifiers, paths, enums, fingerprints and Kernel contracts retain their canonical spelling. Language choice never changes lifecycle gates.

## Current V2 behavior

`pactile task create` creates an English reference scaffold only when no authored PRD exists. It does not translate narrative or regenerate an existing file. The live definition and facts come from the Kernel. Agent-authored prose can use the requested language while preserving those references.

Use `pactile task artifacts <task> --agent` for the compact structured index, and fingerprint-bound fact/document/section reads for the context actually needed. Use the default artifacts view and authored Markdown for human explanation. Do not copy all structured state into prose or imply that editing Markdown updates the Kernel.

The existing `artifact-locale --task` setter operates on legacy `task.json`; V2 has no equivalent per-Task locale field/setter. Do not manually add one to `kernel.json` or promise that the workspace setting translates a V2 scaffold.

## Legacy locale configuration

For an explicitly identified V1 Task, locale resolution uses its valid `meta.artifact_locale`, then `.pactile/config.yaml` `artifact_locale`, then `zh`. The legacy creation templates support `zh` and `en`.

```powershell
pactile task artifact-locale get
pactile task artifact-locale set en
pactile task artifact-locale set zh
pactile task artifact-locale get --task <legacy-task>
pactile task artifact-locale set zh --task <legacy-task>
```

Workspace setters change local configuration and therefore need applicable authorization. Existing authored/archived files are preserved, not translated. Use the supported setter rather than manually editing Task JSON to switch between the two languages.

## Audience and verification

For Agents, keep schemas, typed references and selective retrieval. For people, explain the goal, decisions, risks and evidence in readable prose. Both views refer to the same current facts; neither claims unperformed work.

Verify the actual scaffold/view and preservation behavior separately from language preferences. There is no full CLI internationalization or automatic historical translation requirement. Retrieval/semantic locale and external search locale have separate purposes; do not merge their settings with artifact language.
