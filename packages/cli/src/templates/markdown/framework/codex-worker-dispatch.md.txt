# Codex worker dispatch

Codex work uses independent desktop tasks and cross-session messaging. The main task owns planning, integration, review, and final acceptance. Pactile does not dispatch Codex subagents.

Use `pactile codex prepare <task> --tool create|message|wait|read ...` to bind a Pactile Task and its Kernel revision to a native desktop tool request. Roles are `plan`, `execute`, and `review`; Execute requires recorded user approval and a project worktree. The current Codex desktop task invokes the native tool, then records its returned identity and outcome with `pactile codex receipt <task> <request-id> --result-file <file>`. Inspect `pactile codex status <task>` for pending requests, bound desktop tasks, and stale contracts. An Execute Child holds its Parent's bounded dispatch slot until a completed wait receipt; failed creation releases it. Only create a new desktop task when the user explicitly requests one.

Each worker receives a bounded objective, write set, and acceptance evidence. Record the destination task identity and final evidence in the parent task. A worker message alone does not prove implementation or verification.

The Node CLI does not call the desktop tools directly. A receipt is host-reported evidence, not implementation or acceptance proof. `pactile task` and the Kernel retain phase, approval, and review authority; `pactile pi run` checks execution approval before Pi dispatch. If cross-session coordination is unavailable, continue in the current task and record the reason for serial execution. Do not silently substitute a Codex subagent or a Codex CLI/App Server/ACP session.
