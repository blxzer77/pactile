# 升级 PACTILE

给已经在用旧版 PACTILE 的仓库。不要重做 `init`，不要手搬任务目录。

1. 按发布说明升级 PACTILE 包（或你原来的安装面）。
2. 在项目根目录跑一次 **`pactile update`**。
3. 看摘要：刷新了哪些官方文件、迁了哪些官方规则、哪些进行中的任务仍按旧形状可读、有没有 degraded。
4. **确认一次。** 拒绝则项目保持原状，不会半写。`--force` / `--skip-all` / `--create-new` 会套官方文件，但不算这次确认，也不写停读旗标。
5. 照常开对话或 `/pactile-continue`。进行中的任务还能做、还能收工。

官方面（PACTILE 装进项目的指令与规则）能随这次 `update` 开迁。任务产物先双读，以后再写。确认后才会停读旧形状。从更老的版本一次升上来，也走同一条 `update`。

你改过的官方文件会单独列出并保留。项目里的 **`.pactile/middleware/`** 是中间件 overlay：`pactile init` / `pactile update` **永不写入、不删除、不纳入 hash**。`init` / `update` 会把模块短契约装进 **`.pactile/modules/`**（仅 `index.json` 与各模块 `contract.md`，不含 `catalog.ts`）。默认只把 **smart-search** 标为 required；其余 shipped Provider 为 optional，`init` 不强制安装 MCP。宿主私有 MCP 配置若没有声明为中间件，不进入 Pactile 健康表。失败则回滚或维持双读，项目仍可用。

团队其他人：拉代码即可。若这次只改了本地未提交文件，发布说明会写清谁跑 `update`、谁只要 pull。
