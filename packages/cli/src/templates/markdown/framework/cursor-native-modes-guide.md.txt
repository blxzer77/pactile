# Cursor native modes — bind when native, degrade in one sentence

> **Purpose**: This file is the **Cursor Adapter**. Kernel, Baseline module contracts, and host-agnostic CLI name **slots and capabilities** only. Cursor-specific nouns, probes, and UI drive live **here**. Prefer native; when a surface fails, say **one sentence** (what happened, where it landed) and keep going. Do **not** reimplement modes. Do **not** publish a “this version doesn’t support …” catalog.
>
> **Human lifecycle** (Kernel projection): Open → Define → Approve → Execute → Verify → Integrate? → Close. PACTILE shows up at those three gates and in `prd.md` / `verify.md`. Everywhere else the user should feel they are using Cursor.
>
> **Not a Pactile Task**: official `/goal` / `CreateGoal`. Do **not** restore `pactile-goal`.

---

## Core vs Adapter (zero host coupling)

| Layer | Owns | Must not |
| --- | --- | --- |
| **Core** (Kernel / Baseline contracts / host-agnostic CLI) | Slots: Define, Execute, Evidence, typed worker, isolation, `exact` / `semantic` / `structural` / `external` | `SwitchMode`, `CreateGoal`, Multitask, Canvas, Bugbot, Cursor browser, `.cursor/` as SSOT, Build-probe events |
| **This Adapter** | Evaluate each named Cursor surface; bind or write the one-sentence degrade; visible parallel | Fake a native surface; write those names into Kernel extras / Event Bridge / module contracts |

Host bindings (typed Task names, Multitask, Plan, Goal) belong **only** in this guide. Do not write them back into `worker-orchestration` or Kernel schema.

This guide is **on-demand**. It is not the always-on Bootstrap (`.cursor/rules/pactile-bootstrap.mdc`).

## Experience (Q11–Q14) — function first, invisible unless needed

- **Q11.** The user is using Cursor. PACTILE is visible at Open / Execute / Finalize and on `prd.md` / `verify.md`. One **next native action** is allowed. Do **not** ask the user to type `python` or run CLI — the Agent is the hand.
- **Q12.** Host surface failed → **one sentence**: what happened, and where work already landed. No catalog. No blaming the host.
- **Q13 / Q16.** If a **visible** host parallel surface can open (Multitask / Build in Parallel), open it. There is **no** stable API to open that UI. Ask the user to open it and hand each worker pack. If they do not, `Task()` plus one Q12 sentence. **Do not block.** Same-session silent `Task()` is a degrade and must say so.
- **Q14.** If function is unaffected, do not announce the framework. Must show: the three gates, a Q12 degrade, and (when a task is selected) one next action. **No** opening “loaded” probe. No task → answer directly.

## Mode-specific contracts

### Ask ↔ no-task read-only

- Official Ask does not edit files.
- **Agent tools cannot `SwitchMode` into Ask.** If the user is not already on Ask, stay in Agent and keep the turn read-only.
- Pure Q&A is no-task; no task creation without consent. Answer directly (Q14).
- Side chats during Agent runs are still not Pactile artifacts.

### Plan ↔ Define (Q15, Q23, Q24)

- **Full Define:** `SwitchMode(plan)` immediately. Lite may stay in Agent.
- Default plan save = **home directory** — **Save to workspace**, then the Agent maps into `{TASK}/prd.md` (and `design.md` / `implement.md` as the contract requires).
- **Unlanded Plan must not map to Execute** (Q23).
- Does **not** skip `start-execution --check` / Execute approval.
- No product-code edits until Execute is approved (Q24). A human “start / Build” while still in Define is **A′**, not a skip.
- If Plan switch or save fails: Q12 one sentence and author the same files in Agent.

### Agent ↔ Execute

- Default binding for **Execute**.
- Stay inside the approved Definition / AC (and Full execution/verification contract).
- Contract change → Return-to-Define, then the Execute gate again.
- **Q19:** the main window collects worker **summaries**, conflicts, and gates — not full worker transcripts.

### Debug ↔ evidence in `verify.md`

- Prefer Cursor Debug instrumentation when reachable.
- Always land proof in **`verify.md`**. Adapter does not ship Debug UI instructions.
- Contract change → Return-to-Define. Implementation defect → back to Execute.

### Visible parallel ↔ worker packs (Q13, Q16)

There is **no** stable API to open Multitask / Build in Parallel.

1. Ask the user to open the visible parallel surface and give each worker an explicit pack: `.pactile/tasks/<dir>` + contract slice. Never rely on `selected_task`.
2. If they do not: `Task()` (typed `pactile-implement` / `pactile-check` / `pactile-research` when the enum exists) plus one Q12 sentence. **Do not block.**
3. Silent same-session `Task()` without that sentence is a failed degrade.
4. Pactile remains source of truth for status, gates, integration. This is **not** a Pactile-built parallel product.
5. **Default parallel** when planning has ≥2 isolatable write-sets (Parent children with empty `depends_on`, or Full Task fan-out). Lite / single-file work is not forced into parallel agents.
6. **Serial needs a written reason** (`serial_reason`): shared write-set / HITL or reviewer gate / `depends_on` unmet / user asked serial / conflict surface cannot isolate. HITL, `start-execution --approved`, reviewer gates, and `integrate-child` stay serial (`merge_limit: 1`).
7. Parent alone `integrate-child`. Parallel-first declaration fields live in `.pactile/framework/parallel-first-execution.md` (core contract, host-agnostic).

### Task API honest degrade (`generalPurpose`)

This Cursor Task API may have **no** `pactile-implement` / `pactile-check` enum.

- Dispatch workers as **`generalPurpose`**.
- Do **not** label the run `true-independent`.
- Do **not** nest further implement / check / research Task types from a child worker.
- Parent retains `review-child` / `integrate-child`.

Typed worker names above are **Adapter bindings**. Core contracts speak of typed implement / check / research workers, not these host strings.

### Canvas / Bugbot / Browser / Automations

- **Canvas (Q8):** analysis or inventory deliverables only. Not a second SSOT. No Kernel canvas slot.
- **Bugbot / Security Review (Q7):** optional Verify appendix. Never a substitute for contract Check.
- **Browser (Q10):** when a visible Web UI changed, capture evidence into `verify.md`. Kernel records Evidence, not a browser name.
- **Automations / Loop (Q9):** unbound. Do not add a recurring lifecycle slot.

## Official `/goal` is not a Pactile Task (Q4, Q17, Q21, Q22, Q25)

- Cursor **`/goal`** / **CreateGoal** is a durable **in-window** objective on the Cursor product.
- It is **not** a Pactile task type, not Parent/Child, not `selected_task`, and does **not** skip Execute.
- Do **not** restore `pactile-goal`. Continue / Finish-work / Handoff remain the `/pactile-*` escape hatches.
- **Q17 / Q21:** when definition is already frozen, CreateGoal may drive **this window**. Slot clear → use it; inferring → ask. Goal text = one-line intent aligned with `prd.md` (Q25). Do not paste the PRD. Do not mirror Goal at Open.
- **Q22:** on Close / Finalize, `UpdateGoal` complete or cancel plus one sentence. Goal failure **does not block** Close.
- Definition change → `UpdateGoal`. Goal still does not replace gates or parallel.

User-visible `/` escape hatches on agent-capable Cursor: **`/pactile-continue`**, **`/pactile-finish-work`**, **`/pactile-handoff`**. Internal skills (brainstorm, check, skill-creator, …) are **not** slash commands. `start` is filtered out on agent-capable Cursor.

## Build probe — Adapter dogfood, not Kernel (Q18, Q20, Q24)

Probe the host design-surface **“start doing”** (Plan Build) **only in this Adapter**.

- **Today (Native):** no Build tool. Hooks have no such event. BYOK `ExecutePlanAction` stays out of core.
- **Current path = A′:** after `{TASK}/prd.md` is on disk and `start-execution --check` passes, Execute consent is `start-execution --approved` (or the equivalent human “start / Build” while still in Define — still A′, still the gate).
- **Beta dogfood:** if a later Cursor build exposes a callable Build action, probe it. Landed contract + `--check` PASS → record Execute consent. Unstable / missing → A′ + Q12. Both paths are legal in the 0.5.x beta; the official default is decided before 0.5.0.
- **Forbidden:** Build-probe fields in Kernel extras, Event Bridge default subscriptions, or module contracts. Core stores **approval**, not a host Build event.

## What pactile must not claim

- Plans auto-save into `.pactile/tasks/`.
- Multitask inherits `selected_task` or exposes a stable programmatic mode API.
- Parallel agents cannot conflict without Pactile/worktree discipline.
- `SwitchMode` can open Ask or Debug.
- Shipping a parallel fake Plan/Ask/Debug product, or documenting gaps as product blame.
- Replacing Cursor Multitask with a Pactile scheduler, queue, or new parallel CLI.
- That a `generalPurpose` stand-in is `true-independent`.
- That `/goal` / CreateGoal is a Pactile Task.
- That an unlanded Plan, or a human “Build” before Execute approval, already is Execute.
- That Bugbot / Security Review / Canvas replaced contract Check or task artifacts.
- That a Build probe lives in Kernel extras or Event Bridge.
