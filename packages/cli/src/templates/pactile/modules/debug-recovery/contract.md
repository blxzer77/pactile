# `debug-recovery`

P29 表名：`debug-recovery`（不得改名）。层：on-demand。

## 职责

从可复现失败或重复停滞中恢复。保留失败证据，区分实现、合同、环境、平台及流程循环，选取能改变判断的最小检查；不能靠重复同一假设推进。

## 触发/披露

第一次失败先按当前证据局部诊断；只有重复同质尝试、原因不明或需要更深材料时披露本模块。输入为失败 Run/命令结果、候选和环境事实；输出为可检验的假设、局部修复/环境动作或明确阻塞原因。

执行修复仍受原 write set 和授权约束。重试创建新 Run，保留旧 failed/blocked 记录。合同有误时先与用户协调获授权的支持路径；当前 V2 不承诺自动 Return-to-Define，不手改 Kernel 或覆盖已冻结定义。

## 停止条件

- 每次重复检查都要有新事实、不同假设或明确必需 gate；相同输入下重复全量回归不能算进展。
- 环境或权限缺失时说明具体能力，不把降级结果算原目标成功；需要实际角色保护却不可达时停止危险动作。
- 公开接口、交付物、AC 或写集需要变化时，不自行扩展修复。
- 能解释失败且有针对性回归证据后结束诊断；仍需准确候选的独立 Review。
- 不通过吞异常、跳过校验、删用户数据或弱化测试使结果变绿。

## 关掉必须消失

深诊断指引和循环分析不再注入；运行结果、失败历史、基础验证/授权门仍保留。

## 不得带走

批准；任务定义；Kernel 重试/状态存储；独立 Review；角色动作策略/OS 沙箱；无关环境配置和安装。
