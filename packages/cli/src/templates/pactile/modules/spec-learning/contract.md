# `spec-learning`

P29 表名：`spec-learning`（不得改名）。层：on-demand。

## 职责

将会改变未来决策的稳定知识沉淀到已有项目文档、规范或 ADR。一次性日志、猜测和实现状态留在 Task；代码事实优先由代码/必要测试维护，避免创建重复 SSOT。

## 触发/披露

发现反复发生的原因、稳定接口约定或获用户明确认可的流程改进时按需使用。先查已有文档，提出小范围更新、目标文件、依据和取舍；取得或复用明确适用的用户授权后才写入。

实际授权来自用户交互，记录用于追溯，缺少确认记录不能自动变成写权限。已有明确授权可复用，不要求用户重复批准；无法确认授权适用时停止写入并说明缺口。记录失败不得伪造确认或宣称变更已成功。

输出为更新提案/获授权的文档变更及其来源。无需学习更新可说明原因；没有 V2 必填 learning disposition 或自动 stop 写入机制，不能增加 Kernel Close 门。

## 停止条件

- 不改写用户未批准的长期偏好、全局 Skill、规范或系统文件。
- 临时解法、未证实推断或重复内容不能升格为长期规则。
- 文档与 Kernel 的任务状态/批准/候选事实冲突时先核对，不能用学习条目覆盖运行时合同。
- 需要产品接口或写集变化时，交回定义/执行流程，不借“学习”扩展任务。

## 关掉必须消失

学习提案、持久化步骤和可选学习笔记不再注入；Task 证据、独立 Review 和 Kernel Close 继续有效。

## 不得带走

执行修复；批准；Kernel AC/Review/Close；项目特定规范所有权；个人记忆或 Task 保留清理。
