# `session-transfer`

P29 表名：`session-transfer`（不得改名）。层：on-demand。

## 职责

会话切换时传递足以继续工作的紧凑状态。交接文档是带来源的索引，不是 Kernel 状态、批准或审核证据的替代物。

## 触发/披露

用户请求交接、上下文将耗尽或工作将转入另一获授权会话时使用。默认在已授权的 Task/临时目录写一份 Markdown，不依赖不存在的 slash 命令；已有交接目的地则复用。

交接至少包含：目标与范围、Task ID/schema/revision、Run/candidate ID/fingerprint、批准范围及证据引用、产品 Git 根/分支/base、worktree 实际路径与 dirty 状态、已完成检查和未过门、事实/推断、最小下一动作。敏感信息只传秘密安全引用，不复制凭据、原始提示词或无关个人内容。

接收方先核对当前 Kernel、源文件、候选和资源所有者；状态变化时刷新引用。使用 `pactile task artifacts <task> --agent` 取当前索引，再渐进读事实/文档。没有授权时不代发消息、新建桌面任务、搬移 worktree 或开启实现。

## 停止条件

- 交接与当前状态冲突时，以当前合法来源为准，记录差异后再继续。
- 旧 Review 或旧 Run 候选不能覆盖新的执行结果；未完成、失败和待用户决定项明确保留。
- 写入位置越出批准范围，或内容含密钥/无关数据时停止。
- 串行/并行、宿主替换和恢复动作仍受 Task/Run、依赖、角色和原授权约束。

## 关掉必须消失

便携交接文档及其传输步骤不再要求；Task 原始记录、索引和运行收据仍存在。

## 不得带走

Kernel 生命周期；新的执行/Git/远端授权；Host 调度；worktree 移动/回收；独立 Review。
