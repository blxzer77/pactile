# Pactile Meta

This skill is for local Pactile users who have already run `pactile init` in a project. After reading it, an AI should understand the Pactile architecture, operating model, and customization entry points inside that user project, then modify the generated `.pactile/` and platform directory files according to the user's request.

The default operating scope is local files in the user project:

- `.pactile/`: workflow, config, tasks, spec, workspace, scripts, and runtime state.
- Codex project entry: managed `AGENTS.md` content and `.agents/skills/`.
- Optional native Codex configuration only when a reviewed projection declares it and readiness succeeds.

Codex is the current installation target. Legacy host directories in upgraded projects remain user-reviewable and are not refreshed as active adapters.

Do not assume the user has the Pactile source repository. Do not default to modifying the global npm install directory or `node_modules`.

## How To Use

1. Read `references/local-architecture/overview.md` first to establish the local Pactile system model.
2. If the request involves a specific AI tool, read `references/platform-files/platform-map.md` and the relevant platform file notes.
3. If the user wants to change behavior, read `references/customize-local/overview.md`, then open the specific customization topic.
4. Before editing, read the actual files in the user project and treat local content as authoritative.

## Current Rules

- `.pactile/workflow.md` is the local workflow source of truth.
- `.pactile/config.yaml` is the project-level Pactile configuration and task hook configuration entry point.
- `.pactile/spec/` stores the user's project-specific coding conventions and design constraints.
- `.pactile/tasks/` stores task PRDs, technical notes, research files, and JSONL context.
- `.pactile/workspace/` stores developer journals and cross-session memory.
- Platform settings/config files decide which hooks, agents, skills, commands, prompts, and workflows actually run.
- `.pactile/.template-hashes.json` and `.pactile/.runtime/` are management/runtime state files. Confirm necessity before editing them.

## Do Not

- Do not treat Pactile upstream source code as the default target for local customization.
- Do not modify the global npm install directory or `node_modules/@blxzer/pactile` to implement project needs.
- Do not overwrite user-modified local files with default templates.
- Do not put team-private project rules into the public `pactile-meta`; put project rules in `.pactile/spec/` or a project-local skill.
- Do not describe removed historical mechanisms as current Pactile behavior.
