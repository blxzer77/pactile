# 先复用，再实现

[English](reuse-first.md) | 简体中文

Pactile 的 Define、Execute、Verify Skill 会引导 Agent 读取安装后的
`.pactile/framework/reuse-first-guide.md`。新安装与升级使用同一模板注册表，
Skill 仍经过 projection ownership 检查。用户改过的宿主 Skill 会保留并要求显式
解决冲突；安装成功本身不能证明这些保留文件已经采用新要求。

选择方案前先检查项目和环境已有能力，再通过获准搜索主动评估成熟外部方案。
比较适配、维护、许可证、运行时/平台、依赖负担、接入与长期维护成本；合适时
复用并保持接入层简洁。有具体缺口或总成本优势时可以自研，同时说明维护责任。

把选择、证据和未知事实写入 Task `design.md` 的 Decision/Rationale/Risk 分节。
现有结构化工件索引能发现这些人工撰写的分节并按当前 fingerprint 展开，无需
增加运行时决策数据库、搜索引擎或依赖。

## 效率与边界

- 需求、环境与证据仍适用时引用已有研究；小修无需重复方案调查，只更新变化的事实。
- 尊重明确从零设计的指令，记录该指令、理由与实现风险。
- 搜索不可用或被禁止时，说明边界，区分本地证据与未证实外部判断，在已有授权内继续。
- 调研何时足够取决于实际决策，不设形式化搜索次数。
- 审核关注交付行为和选择依据，依赖数量或搜索记录都不是单独的通过条件。

该指引不授予网络、安装或数据外发权限。baseline Tile 策略与项目隐私规则继续
生效；使用宿主/项目已授权能力，不强制某个 Provider、模型或代理。提示词是行为
要求，不是操作系统沙箱，也不能保证模型永远遵守。批准、独立 Review 与 Kernel
Close 门保持有效。

精简记录借鉴 [MADR](https://adr.github.io/madr/) 的决策与理由思路，不要求安装
其包或复制模板。评估 npm 方案时可用[官方包元数据说明](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/)
核对许可证、兼容性等；元数据本身不能证明维护情况或适用性。
